# nova — определение процента грязи в металоломе

Оценка засорённости привозимого металолома по видео с камер приёмной площадки.
Единица измерения — **сессия**: одна машина от подъезда до выезда.

## Что выяснилось о данных

Датасет: `../папки машин УПП`, 24 ГБ, **198 клипов, 84 сессии**, ~8.2 часа видео.
Папка = одна машина, в имени папки госномер — это готовая ручная разметка сессий
от оператора, используется как ground truth для проверки автомата.

### Камер не две, а пять, и они не синхронны

| Канал | Что видно | Клипов | fps (медиана) | Роль |
|---|---|---:|---:|---|
| **246** `ESP-DSP-15` | обзор всей площадки сверху | 102 | 6.1 (2–25) | сессии, детект машины |
| **239** | куча, сброс из грейфера | 45 | 2.9 | пыль при сбросе |
| **238** | кузов сверху, освещённая зона | 37 | 7.0 | содержимое кузова |
| **235** | кузов крупным планом сбоку | 9 | 2.5 | **лучший ракурс для грязи** |
| **161** `UPP-FER-PTZ` | поворотная, машина мелкая | 2 | 24.7 | не использовать (PTZ) |

**Камеры из кабины машиниста в датасете нет.** Ни одного клипа.

**Параллельных записей нет:** в каждой папке клипы только одного канала.
Мультикамерное слияние на этих данных не проверить.

### Ловушки

1. **Метаданные fps врут.** cv2 сообщает 600 fps / 71340 кадров там, где реально
   834 кадра за 120 с (~7 fps). Реальный fps считается как
   `число видеопакетов / длительность из имени файла` — см. `novadirt/video.py`.
   Если считать время по номеру кадра, вся сессионная логика поедет.
2. **fps низкий и плавает: 2–25.** Оптический поток и трекинг динамики пыли
   при 2–3 fps нерабочи — облако между кадрами успевает рассеяться.
   Поэтому грязь меряем **покадровой сегментацией содержимого кузова**,
   а пыль оставляем вторым, подтверждающим сигналом.
3. **Часть клипов без таймкода в имени** (`283.avi`, `985.avi`) — время только
   из вшитого в кадр таймштампа (OCR).

### Предобученная YOLO (COCO) главную камеру не тянет

Проверено на `yolo11x`: на 246 днём грузовик **не найден вообще**, ночью
conf 0.35–0.40. На 235 крупным планом — `truck 0.91`. Кузов на 238 определился
как `boat 0.34`. **Ковша в COCO нет как класса.** Нужен свой детектор.

## Структура

```
novadirt/clips.py     индексация датасета, парсинг таймкодов из имён
novadirt/video.py     чтение клипов, восстановление реального fps
novadirt/session.py   конечный автомат сессии (гистерезисный)
scripts/01_index.py         отчёт по датасету и fps
scripts/02_probe_yolo.py    проверка COCO-модели по каналам
scripts/03_extract_trainset.py  выборка кадров под разметку
scripts/04_prelabel.py      предразметка грузовиков в формат YOLO
scripts/05_train_det.py     сплит по сессиям + обучение детектора
scripts/06_eval_det.py      метрики детектора в разрезе канал × день/ночь
labeler/server.py     редактор разметки: боксы (det) и полигоны (seg)
tests/                pytest
```

Запуск разметчика: `.venv/bin/python -m labeler.server` → http://127.0.0.1:8100

## Две задачи разметки, а не одна

Общий план и крупный решают разное, форматы YOLO-det и YOLO-seg несовместимы
в одном `.txt` — поэтому разметки две, независимые, обе в `labeler` (вкладки
«боксы» / «полигоны»).

### Детекция боксами — `labels/`, каналы 246, 161

`0 truck` · `1 truck_body` (кузов) · `2 grapple` · `3 excavator`

Предразметка (`04_prelabel.py`) закрывает только `truck` низким порогом 0.15 —
recall важнее precision, лишний бокс удалить дешевле, чем нарисовать пропущенный.
Остальное руками.

### Сегментация полигонами — `labels_seg/`, каналы 235, 238, 239

`0 grapple` · `1 scrap`

Процент грязи считается по пикселям лома, и железо грейфера в эту площадь
попадать не должно. **Боксом ковш из области не вычесть**: в прямоугольнике
ковша сам ковш занимает около трети, остальное — груз и фон, вычитание бокса
из бокса выкинуло бы половину полезных пикселей. Отсюда полигоны.

На 246 (площадка с 30 м) и 161 (PTZ) полигоны не размечаются: ковш там
несколько десятков пикселей, граница лома не читается. `labeler` в режиме
сегментации эти каналы просто не показывает — 738 кадров из 1354.

### Область внимания (ROI) не размечается

ROI вокруг ковша нужен, чтобы на инференсе не гонять тяжёлую сеть по всему
кадру. Но чтобы им воспользоваться, его надо сначала *предсказать* — а
предсказывался бы он по ковшу. Круг: сеть учили бы воспроизводить формулу,
которая пишется в пять строк от полигона ковша. Плюс рука обводит «область
рядом» по-разному в каждом кадре, и этот разброс лёг бы в данные навсегда.
Поэтому ROI — код на инференсе (`bbox(grapple)` расширить, коэффициент
переподбирается без переразметки), а не класс.

## Перенос на другую машину

В репозитории **разметка есть, а кадров нет**: 1354 jpg весят 808 МБ, и они
полностью воспроизводимы из исходных видео. Выборка детерминированная
(фиксированный шаг по кадрам, сортировка клипов), имена файлов от пути к
датасету не зависят — поэтому восстановленные кадры сходятся с `labels/`
один в один.

```bash
git clone https://github.com/FireStar108/nova.git && cd nova
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python torch torchvision ultralytics \
    opencv-python-headless numpy supervision lap pytest fastapi uvicorn

# восстановить кадры из датасета (папки машин УПП, 24 ГБ)
.venv/bin/python scripts/03_extract_trainset.py --root "<путь>/папки машин УПП"

# проверить, что кадры сошлись с разметкой
ls out/trainset/images | wc -l    # 1354
.venv/bin/python scripts/05_train_det.py --split-only
```

Если имён окажется меньше 1354 — значит часть клипов не читается на новой
машине (кодеки), и сплит просто пропустит кадры без пары; разметка при этом
не портится.

## Обучение детектора

```bash
.venv/bin/python scripts/05_train_det.py --split-only   # только собрать сплит
.venv/bin/python scripts/05_train_det.py                # yolo11s, 100 эпох
.venv/bin/python scripts/06_eval_det.py                 # метрики по группам
```

Сплит **по сессиям, а не по кадрам** (`out/det_split`). Кадры одной сессии
сняты одной камерой с одной машины с интервалом в секунды: случайный покадровый
сплит положил бы почти одинаковые кадры в train и val, и mAP@val показал бы
0.95 там, где на новой машине модель не работает. Отбор детерминированный, с
сохранением доли ночных сессий: 84 сессии → 67/17, 1044/310 кадров.

### Обучаются два класса из четырёх

Размечено вручную 1354 кадра: `truck` 2255 объектов, `grapple` 1306,
**`truck_body` 12, `excavator` 4**. Последние два из обучения исключены —
на десятке примеров классу не научиться, а в метриках они дают только шум.
`05_train_det.py` выбрасывает их и перенумеровывает остальные в
`0 truck` / `1 grapple`, печатая, что и сколько выброшено.

Отсюда следствие для `session.py`: начало разгрузки там определяется по доле
площади ковша внутри бокса **кузова**, а класса кузова у детектора теперь нет.
Признак придётся переделать на бокс `truck` целиком либо доразметить кузов.

Боксы размечены на всех пяти каналах, а не только на общих планах, поэтому
детектор учится по всем — ковш на 235/238/239 нужен для ROI на инференсе.

Метрики (`06_eval_det.py`) считаются **отдельно по каналу и времени суток**:
246 днём и 246 ночью — разные по сложности задачи (см. `02_probe_yolo`), и
сводная цифра прячет провал одного из режимов. Имена классов читаются из
`dataset.yaml` сплита, а не дублируются в коде.

### Состояние

Обучение оборвано на 8-й эпохе (M2 тормозит: первые эпохи по 78 с, дальше
~470 с — 100 эпох заняли бы ~13 часов). Лучшие веса — эпоха 7, **mAP50 0.669**,
mAP50-95 0.358. Полный прогон планируется на более мощной машине.

## Автомат сессии

`IDLE → TRUCK_PRESENT → UNLOADING → IDLE`, переходы гистерезисные (требуют N
подтверждающих кадров подряд), иначе моргание детектора рвёт сессию на части.

Начало разгрузки определяется не по IoU ковша и кузова, а по **доле площади
ковша внутри бокса кузова**: ковш много меньше кузова, IoU остаётся мизерным
даже когда ковш полностью внутри, и порог по нему не выставить.

Итоговый процент — среднее **взвешенное по площади захвата**: маленький грязный
ковш не должен весить столько же, сколько большой чистый.
